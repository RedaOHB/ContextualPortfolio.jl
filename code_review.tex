\section{Overview}
%=============================================================================

The \texttt{ContextualPortfolio.jl} package implements contextual portfolio
optimization using conditional moments and a rolling-window backtesting framework.
The review covered all source files (\texttt{src/}), test files (\texttt{test/}),
project configuration (\texttt{Project.toml}), documentation (\texttt{README.md},
\texttt{docs/}), and metadata (\texttt{CITATION.cff}, \texttt{LICENSE}).

Issues are classified by severity:
\begin{description}[style=nextline]
  \item[Critical] Prevents the package from loading or producing correct results.
  \item[Bug] Causes runtime errors on specific code paths.
  \item[Important] Affects usability, reproducibility, or packaging standards.
  \item[Minor] Typographical or stylistic issues.
\end{description}

\section{Line Ending Corruption (All Files)}
\label{sec:crlf}
%=============================================================================

\textbf{Severity:} Important\\[0.3em]
All 29 tracked files had been converted from Unix line endings (LF) to Windows
line endings (CRLF), producing a spurious diff of 5\,154 lines (2\,577 insertions,
2\,577 deletions) with no actual content changes. This was confirmed with:

\begin{lstlisting}[language=bash, numbers=none]
git diff --ignore-cr-at-eol --stat
# (empty output: no content changes)
\end{lstlisting}

\textbf{Fix applied:} Reverted all files to their committed LF state via
\texttt{git checkout -- .} before applying any further corrections.

\subsection{Missing Dependencies in \texttt{Project.toml}}
\label{sec:project-toml}
%-----------------------------------------------------------------------------

\textbf{Severity:} Critical\\
\textbf{File:} \texttt{Project.toml}\\[0.3em]
The \texttt{[deps]} section listed only \texttt{Documenter}, while the module
imports 18 packages:

\begin{lstlisting}
# src/ContextualPortfolio.jl
using JuMP, Gurobi
using DataFrames, Dates, DelimitedFiles, ExcelFiles, XLSX
using Distributions, CovarianceEstimation, LinearAlgebra,
      Random, Statistics, StatsBase

Without these entries, \texttt{Pkg.add("ContextualPortfolio")} cannot resolve
dependencies and the package cannot be loaded.

\textbf{Fix applied:} Added all 18 runtime dependencies with their correct UUIDs
(retrieved from the Julia General registry). Moved \texttt{Documenter},
\texttt{CSV}, and \texttt{Test} to the \texttt{[extras]} section. Added a
\texttt{[targets]} section for test dependencies. Updated the \texttt{authors}
field to include both authors.

%-----------------------------------------------------------------------------
\subsection{Double Includes in \texttt{backtest.jl}}
\label{sec:double-include}
%-----------------------------------------------------------------------------

\textbf{Severity:} Critical\\
\textbf{File:} \texttt{src/backtest.jl}, lines 1--5\\[0.3em]
The file began with:

\begin{lstlisting}
include("models.jl")
include("moments.jl")
include("splitting.jl")
include("utils.jl")
include("performance.jl")
\end{lstlisting}

These files are already included by \texttt{src/ContextualPortfolio.jl}
(lines~11--16). Double inclusion redefines all functions and, critically, attempts
to redefine \texttt{struct backtestParameters}, which Julia does not allow.
This causes an \texttt{ErrorException} on module load.

\textbf{Fix applied:} Removed the five \texttt{include} statements from
\texttt{backtest.jl}.

%-----------------------------------------------------------------------------
\subsection{Incorrect \texttt{nothing} Check in \texttt{backtest.jl}}
\label{sec:nothing-check}
%-----------------------------------------------------------------------------

\textbf{Severity:} Critical\\
\textbf{File:} \texttt{src/backtest.jl}, lines 53 and 75\\[0.3em]
The code tested:

\begin{lstlisting}
if params.context == :nothing
\end{lstlisting}

Here \texttt{:nothing} is a \texttt{Symbol}, not Julia's \texttt{nothing} singleton.
Since the field is typed \texttt{Union\{DataFrame,Nothing\}}, this comparison
always evaluates to \texttt{false}, meaning the no-context branch is never taken.

\textbf{Fix applied:} Replaced both occurrences with \texttt{isnothing(params.context)}.

%-----------------------------------------------------------------------------
\subsection{Unqualified Variable References in \texttt{backtest.jl}}
\label{sec:unqualified}
%-----------------------------------------------------------------------------

\textbf{Severity:} Critical\\
\textbf{File:} \texttt{src/backtest.jl}, lines 55, 58, 61, 62\\[0.3em]
Several lines referenced bare \texttt{returns} and \texttt{context} instead of
\texttt{params.returns} and \texttt{params.context}:

\begin{lstlisting}
data = returns                  # line 55
data = align(returns, context)  # line 58
n = size(returns[:,2:end], 2)   # line 61
d = size(context[:,2:end], 2)   # line 62
\end{lstlisting}

These would raise \texttt{UndefVarError} at runtime since no global variables
\texttt{returns} or \texttt{context} exist.

\textbf{Fix applied:} Prefixed all references with \texttt{params.}. For the
\texttt{d} variable, added a guard with \texttt{isnothing} to handle the
no-context case.

%-----------------------------------------------------------------------------
\subsection{Input Mutation in \texttt{moments.jl}}
\label{sec:mutation}
%-----------------------------------------------------------------------------

\textbf{Severity:} Bug\\
\textbf{File:} \texttt{src/moments.jl}, lines 28--29\\[0.3em]
The function \texttt{conditional\_moments} modifies its \texttt{data} argument
in-place during standardization:

\begin{lstlisting}
data[:,1:n-d] = (data[:,1:n-d] .- mu_return) ./ sigma_return
data[:,n-d+1:end] = (data[:,n-d+1:end] .- mu_context) ./ sigma_context
\end{lstlisting}

Since \texttt{data} is a \texttt{Matrix}, this mutates the caller's array, causing
incorrect results on subsequent iterations of the rolling window.

\textbf{Fix applied:} Added \texttt{data = copy(data)} at the start of the function.

%-----------------------------------------------------------------------------
\subsection{Misleading \texttt{diagind} in \texttt{models.jl}}
\label{sec:diagind}
%-----------------------------------------------------------------------------

\textbf{Severity:} Minor\\
\textbf{File:} \texttt{src/models.jl}, line 137\\[0.3em]
The code used \texttt{diagind($\Sigma$)} to index into \texttt{$\Sigma$\_mu}:

\begin{lstlisting}
Sigma_mu[diagind(Sigma)] = diag(Sigma)
\end{lstlisting}

Although both matrices are $n \times n$ (so the indices coincide), this is
misleading. Changed to \texttt{diagind($\Sigma$\_mu)} for clarity.

\section{Solver Abstraction: Gurobi $\to$ Clarabel Default}
\label{sec:solver}
%=============================================================================

\textbf{Severity:} Enhancement\\[0.3em]
The package previously hard-coded \texttt{Gurobi.Optimizer} in all three
optimization functions and required Gurobi as a dependency. Gurobi is a
commercial solver requiring a license, which creates an installation barrier
for users without academic or commercial access.

All three models (\texttt{optimize\_mv}, \texttt{optimize\_mvbu},
\texttt{optimize\_mveu}) solve convex quadratic programs, which are fully
supported by the open-source solver Clarabel.

\textbf{Changes applied:}

\begin{enumerate}
  \item \textbf{\texttt{src/models.jl}}: Added an \texttt{optimizer} keyword
    argument (default: \texttt{Clarabel.Optimizer}) to all three functions.
    Replaced Gurobi-specific solver attributes (\texttt{OutputFlag},
    \texttt{TimeLimit}) with solver-agnostic JuMP functions
    (\texttt{set\_silent}, \texttt{set\_time\_limit\_sec}).

  \item \textbf{\texttt{src/backtest.jl}}: Added an \texttt{optimizer} field
    (type \texttt{Any}, default \texttt{Clarabel.Optimizer}) to the
    \texttt{backtestParameters} struct. The field is passed through to all
    model calls via the \texttt{optimizer} keyword.

  \item \textbf{\texttt{src/ContextualPortfolio.jl}}: Changed
    \texttt{using Gurobi} to \texttt{using Clarabel}.

  \item \textbf{\texttt{Project.toml}}: Replaced the \texttt{Gurobi}
    dependency with \texttt{Clarabel}.

  \item \textbf{\texttt{test/runtest.jl}}: Changed \texttt{using Gurobi} to
    \texttt{using Clarabel}.

  \item \textbf{\texttt{docs/src/tutorial.md}}: Updated the setup imports.

  \item \textbf{\texttt{README.md}}: Added a ``Solver'' section explaining
    how to use a custom optimizer, with Gurobi as an example.
\end{enumerate}

Users who prefer Gurobi (or any other JuMP-compatible QP solver) can pass it
explicitly:

\begin{lstlisting}
using Gurobi
Parameters = backtestParameters(..., optimizer=Gurobi.Optimizer)
\end{lstlisting}

The module imported 18 packages via \texttt{using}, but only 9 are actually
used in the core source files (\texttt{src/}). The remaining 9

and backtesting functionality.

\textbf{Fix applied:} Removed all unused packages from \texttt{using} in the
module file and from \texttt{[deps]} in \texttt{Project.toml}. The core
dependencies are now: \texttt{JuMP}, \texttt{Clarabel}, \texttt{DataFrames},
\texttt{Dates}, \texttt{Distributions}, \texttt{CovarianceEstimation},
\texttt{LinearAlgebra}, \texttt{Statistics}, \texttt{StatsBase}.
